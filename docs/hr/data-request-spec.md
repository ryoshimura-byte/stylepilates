# データ請求仕様書（評価KPI測定用）

半期評価（2026年9月）の4軸KPIのうち **量・顧客支持・質** を測定するために必要なデータの請求仕様です。
**受け取る側がそのまま抽出作業に入れる粒度**で書いています。

- 作成：マーケティング部
- 請求先：**（A）会員LTV分析シート管理者（深井さん）** ／ **（B）Square データ抽出担当**
- 関連：[KPI測定仕様書](kpi-measurement-spec.md)（各列が何の計算に使われるかの根拠）

> **実データは本リポジトリに置きません。** 受け渡しは権限限定の共有フォルダで行います（§5）。

---

## 0. 依頼の趣旨（30秒で読む部分）

評価制度の4軸KPIのうち3軸が、**個人別データが無いために測定できません。**
数字を推定で埋めて評価することはしないため、データが届かない軸は「欠測」として
評価に使わない運用になります。つまり **このデータが揃わない限り、評価の3/4が空欄のまま**です。

特に質軸（5ヶ月目突破率・12ヶ月継続率）は、
**「会員×月の担当者が誰だったか」の履歴が無ければ、定義上まったく計算できません。**
制度表でも「時系列タブ依頼中★」として積み残しになっている部分です。

## 1. 最初に答えていただきたい3つの質問（データ抽出の前に）

> **この3問の答えで、何が測定可能かが決まります。抽出作業より先にご回答ください。**
> 抽出に着手する前に確認したいのは、無駄な作業をお願いしないためです。

### Q1【最重要】Squareに「カスタマー担当（主担当）」に相当する登録項目はありますか。ある場合、**履歴として最も古い日付はいつ**ですか。

- カスタマー担当は制度設計上 2026-09-01 に新設された概念です。それ以前の登録が無い可能性があります。
- **12ヶ月継続率には 2025年5月からの担当履歴が必要**です。
- **5ヶ月目突破率には 2025年12月からの担当履歴が必要**です。
- 履歴が無い期間について、**担当を後から割り当てることはお願いしません**（評価の恣意性を生むため）。
  「無い」というご回答で十分です。その場合は当該指標を欠測として処理します。

| Q1 の答え | 帰結 |
|---|---|
| 2025年5月以前から履歴あり | 5ヶ月目突破率・12ヶ月継続率とも測定可能 |
| 2025年12月〜2026年前半から履歴あり | 5ヶ月目突破率は測定可能。12ヶ月継続率は部分測定または欠測 |
| 担当登録の項目自体が無い／履歴が残らない | **質軸は全面的に欠測。** 代わりに担当割当の運用開始日を決め、そこから起算する |

### Q2 予約データで「指名予約か否か」と「指名先スタッフ」が、**プラン別**に取得できますか。

- 指名インセンティブがベーシックプラン限定のため、プラン別に分解できることが必須です。
- 取得できない場合、指名件数は全プラン合算でしか出せず、評価に使える形になりません。

### Q3 レッスン枠に「指名予約を受け付ける枠か」の属性はありますか。

- 指名率の分母に使います（[KPI測定仕様書](kpi-measurement-spec.md) §3-2）。
- 無い場合は、**分母を「当該スタッフが実施した枠に紐づく実施済み予約数」で代用**します。
  その場合は暫定定義である旨を評価シートに明記します。ご回答だけいただければ結構です。

## 3. 粒度について ―― なぜ「会員×月」が必要で、「スタッフ×月の集計」では足りないのか

「スタッフ別の継続率を出して送ってください」という依頼の仕方をしていないのには理由があります。

| 理由 | 説明 |
|---|---|
| **① 按分が会員単位でしか計算できない** | 担当の按分は「会員 i の1〜5ヶ月目のうち何ヶ月担当したか（m_i / 5）」で決まります。会員ごとに m が違うため、集計済みの表からは復元できません |
| **② 除外条件が会員単位の属性** | 不可抗力退会（転居・妊娠等）を分母から除きます。集計後では除けません |
| **③ 担当変更の履歴が潰れる** | 集計表では「途中から担当した会員」と「最初から担当した会員」が同じ1名になります |
| **④ 定義の一致を担保できない** | 集計を各自が行うと、休会の扱い・端数処理・除外の線引きが人によってずれます。**生データを一箇所で受け取り、集計は1つの定義で行う**のが、CLAUDE.md の「定義の違いを特定する」という原則の実装です |
| **⑤ 集計側の手間が減る** | 結合や条件分岐はこちらで行います。抽出条件を単純にできる分、作業は軽くなります |

> **お願い：集計・加工はせず、生データのままお送りください。**
> 「見やすくする」ための小計行・色分け・結合セルは、かえって機械処理を壊します。

## 4. 対象期間

| テーブル | 対象期間 | 根拠 |
|---|---|---|
| **T1 会員マスタ** | **2024年10月1日以降に入会した全会員**（退会者含む） | 12ヶ月継続率のコホート（2025年5〜9月入会）＋前期比較のため半年遡る |
| **T2 会員×月 時系列** | **2024年10月 〜 2026年8月**（23ヶ月） | 12ヶ月コホートの1〜12ヶ月目をすべてカバーするため |
| **T3 担当履歴** | **存在する全期間**（最古の日付を明記） | Q1 の確認そのもの |
| **T4 実施明細** | **2025年10月1日 〜 2026年8月31日** | 当期（4〜9月）＋前期（10〜3月）。3月評価との連続性のため |
| **T5 予約明細** | **2025年10月1日 〜 2026年8月31日** | 同上 |
| **T6 シフト枠** | **2025年10月1日 〜 2026年8月31日** | 同上 |

**2026年9月分は含めません。** 評価実施月は月末で締まっておらず、
締まっていない月を入れると面談の日取りで数字が変わるためです（[KPI測定仕様書](kpi-measurement-spec.md) §1-1）。

> **期間が長くて負担が大きい場合の優先順位：**
> ① T4・T5 の **2026年6〜8月**（量軸・顧客支持軸が動く最小セット）
> ② T2・T3 の **2025年12月〜2026年8月**（5ヶ月目突破率が動く最小セット）
> ③ 残りの期間（前期比較・12ヶ月継続率）
> ①だけでも先に進められます。全部揃うまで待つ必要はありません。
